# The Baker's Dozen: Coq proof of halting and a score lower bound

    The Baker's Dozen = 1RB1RA_1RI1RC_0LD1LG_0RE1LD_1LK1RF_1RG0RA_1RA0LH_1LG1LH_1RE0LJ_1LH1LI_0LM0LL_1RL1LK_0LG---

The Baker's Dozen is Jeff Ketchersid's M12 with L0 = 1RL (was 0LH), K0 = 0LM (was the halt) and a new state M = (0LG, ---).
It halts from the blank tape in state M reading a 1 (M1 undefined).

Everything below is machine-checked with Coq 8.20.1 against busycoq commit `bd2e36f`. Every main theorem is
closed under the global context: no `Admitted`, no `Axiom`, no `Parameter` (`probe.log`: 17 of 17
`Print Assumptions` closed).

This folder holds none of Jeff Ketchersid's files or proofs. The proof files are assembled at build time from the
templates here and his files, which `build.sh` fetches from his repository. See [How to rebuild](#how-to-rebuild).

## What is proved

In `BB13_BakersDozen.v`:

    Theorem halt : halts tm c0.

In `BB13_BakersDozen_bound.v`:

    Theorem score_exact :
      exists c, c0 -->* c /\ halted tm c /\ ones c (fst pb4 + snd pb4 / 2 + 3).

    Theorem sigma_lower_bound :
      exists c N, c0 -->* c /\ halted tm c /\ ones c N /\
      f_omega2 (f_omega2 (f_omega2 (f_omega2 (f_omega (f_omega 4))))) < N.

    Theorem sigma_lower_bound_strong :
      exists c N, c0 -->* c /\ halted tm c /\ ones c N /\
      f_omega2 (f_omega (f_omega2 (f_omega (f_omega2 (f_omega (f_omega2 (f_omega (f_omega 4)))))))) < N.

    Theorem beats_M12_bound :
      exists c N, c0 -->* c /\ halted tm c /\ ones c N /\
      f_omega2 (f_omega1 (f_omega1 3)) < N.

    Theorem beats_M14_bound :
      exists c N, c0 -->* c /\ halted tm c /\ ones c N /\
      f_omega2 (f_omega2 (f_omega2 15)) < N.

- `tm` is the Baker's Dozen's table. `probe.v` checks it entry by entry against the machine string (26 `eq_refl` checks
  generated by `gen_probe.py` from the string, not copied from the `.v`).
- `ones c N` (Jeff's definition) says that the tape of `c` has exactly N ones.
- `pb4 = Kd_iter (d4 / 3) (7, 3)`, where d1 = round2 5, d2 = round2 d1, d3 = round2 d2 and d4 = round2 d3, and
  `round2 d = fst pa + snd pa / 2 + 2` with `pa = Kc_full (Kd_iter (d / 3) (7, 3))`. `Kc_full`, `Kd_step` and
  `Kd_iter` are Jeff's functions from `BB12_M12.v`, built on W.
- The hierarchy is Jeff's (`BB12_M12_bound.v`): f 0 n = n + 1, f (k+1) n = (f k)^n (n), f_omega n = f n n,
  f_omega1 n = f_omega^n (n), f_omega2 n = f_omega1^n (n). So the main bound reads
  f_(ω+2)^4(f_ω(f_ω(4))) < N.

**Score convention.** The Baker's Dozen's halting transition is read on a 1. Under the standard convention it writes a 1 (1RZ),
which changes nothing, so the score is σ = N, the number of ones in the halted configuration. That is the N in the
theorems, and the bound is strict: f_(ω+2)^4(f_ω(f_ω(4))) < σ. (M12, by contrast, halts on a 0 with 1RZ, so σ = N + 1
there, and Jeff's theorems are stated with `< N + 1`.)

**Comparison with M12 and M14.** The two `beats_` theorems compare the Baker's Dozen's score with the lower bounds
that Jeff Ketchersid's Coq files prove for M12 and M14 (github.com/jeff87654/busy-beaver at commit `f7975bf`). Those
files define `iter`, `f`, `f_omega`, `f_omega1` and `f_omega2` exactly as here, so the bounds are the same numbers.

In `BB12/verify_m12/multifile/BB12_M12_bound.v`:

    Theorem sigma_lower_bound_m12 :
      exists c N, c0 -->* c /\ halted tm c /\ ones c N /\
      f_omega2 (f_omega1 (f_omega1 3)) < N + 1.

In `BB14/verify/multifile/BB14_M14_bound.v`:

    Theorem sigma_lower_bound :
      exists c N, c0 -->* c /\ halted tm c /\ ones c N /\
      f_omega2 (f_omega2 (f_omega2 15)) < N + 1.

M12 and M14 both halt on a 0 with 1RZ, so their score is N + 1 and these say bound < σ. The Baker's Dozen's score is
N, so `beats_M12_bound` and `beats_M14_bound` say that its σ exceeds f_(ω+2)(f_(ω+1)(f_(ω+1)(3))) and
f_(ω+2)³(15). Both follow from `sigma_lower_bound` by monotonicity (`M12_bound_le`, `M14_bound_le`), using
f_ω(f_ω(4)) ≥ 15 (`f_omega_f_omega_ge15`) and f_(ω+1)(y) ≤ f_(ω+2)(y) for y ≥ 1 (`f_omega1_le_f_omega2`).
These are comparisons of proved bounds: they show that the Baker's Dozen's score is larger than what has been
proved about M12 and M14, not that it is larger than their actual scores. On 28 October 2026 Jeff Ketchersid and
Argon published M13b and M14b, whose proved bounds f_(ω+2)^6(f_(ω+1)(f_(ω+1)(3))) and
f_(ω+2)^9(f_(ω+1)(f_(ω+1)(3))) are larger than the Baker's Dozen's.

## How the proof goes

Configurations are Jeff's: `Ce p a c d = 0^∞ (10)^p 1^(a+2) I> (10)^c 0 (10)^d 0^∞` and
`Cd p b d = 0^∞ (10)^p 1^(b+2) I> (10)^d 0^∞`.

| rule | Coq | statement | source |
|---|---|---|---|
| KC | `CE_EVEN` | `Ce (S p) (2k) (S c) d -->+ Ce (p + S k) (W p 1) c d` | Jeff, unchanged |
| CREL | `C_REL` | `Cd (S p) (2m+1) (S d) -->+ Ce p (W p 3) m d` | Jeff, unchanged |
| DSTEP | `D_STEP` | `Ce p a 0 (S (S d)) -->+ Cd p (W p (a+4)) d` | Jeff, unchanged |
| START | `START` | `c0 -->* Cd 7 3 5` (260 literal steps) | new |
| RST | `RST` | `1 <= p + k -> Ce p (2k) 0 0 -->+ Cd 7 3 (p + k - 1)` | new |
| D1 | `D1` | `Ce p a 0 1 -->+ Ce p (a + 6) 0 0` (6 steps) | new |
| G | `G_HALT` | `Cd (S p) (2m+1) 0 -->+ c_halt p m`, halted, M reading a 1 | new |

RST is the composition `RST_entry` (I0, E0, Jeff's `cr_KL_11_10`), `RST_sweep` (induction; one step of it is K1 L0
L0 L1 K1 L1), `RST_restart` (11 steps through K0 = 0LM and M0 = 0LG) and `STARTUP` (168 literal steps that consume
four counter pairs and never read the rest). G is Jeff's `HALT_step` followed by one K0 step.

Jeff's composition lemmas `Kc_loop`, `Kc_full_all`, `Kd_step_all` and `Kd_loop` are reused unchanged. A round is
`round2_run`: from `Cd 7 3 d` with d mod 3 = 2, Kd_loop does d/3 Kd steps, Kc_full_all, D1 and RST, and the
round ends at `Cd 7 3 (round2 d)`.

**Halting by residues.**
- `W2_pow`: 2·W 2 y + 5 = 3^(y+3).
- `W_pow3`: for j ≥ 2, 2·W j b + 5 = 3^(y+3) for some y ≥ b.
- `W_mod81`: W j b ≡ 38 (mod 81) for every j ≥ 3 and every b.
- Every accumulator in the run is at level ≥ 3. So `Kc_res`, `Kc_iter_res`, `Kc_full_res`, `Kd_step_res` and
  `Kd_iter_res` track p mod 81, and `round2_res` gives round2 d ≡ 46 + 67·(d/3) (mod 81).
- From d0 = 5, this gives d1 ≡ 32 (mod 81), d2 ≡ 14 (mod 27), d3 ≡ 8 (mod 9) and d4 ≡ 0 (mod 3)
  (`d1_res` … `d4_res`). Rounds 0–3 restart, and round 4 ends at `Cd (fst pb4) (snd pb4) 0`, where G halts.
  This is `run_halt`, and from it `halt`.

**The bound.**
- Seed: `seed_dom` gives ok_pb (f_ω 4) for the round-0 Kd step. It uses Jeff's `W_omega_bound` and `W_mono`, and
  a new lemma `W_level_ge` (W is monotone in the level).
- Rounds: `round_dom` gives ok_pb (f_ω2 (f_ω B)) for the next round's pb from ok_pb B for the current one. It uses
  Jeff's `Kc_full_dom` and `Kd_iter_dom`, a new catch-up lemma `catch_up`
  (f_ω2 (n/2) ≤ f_ω1^n (N) for N ≥ 1) and `f_omega1_dbl`.
- Four rounds give `pb4_dom_strong`. `ok_pb_score` turns that into the score bound, and `chain4_ge` weakens it to
  the plain form.

## What is Jeff Ketchersid's and what is new

The base is Jeff Ketchersid's Coq development for M12, `BB12/verify_m12/multifile/BB12_M12.v` and
`BB12_M12_bound.v` in [github.com/jeff87654/busy-beaver](https://github.com/jeff87654/busy-beaver), read at commit
`f7975bf`. M12 was found and proved by Argon, a Google Gemini model run by Jeff, and Jeff re-checked the Coq files.
The proof architecture here is theirs: the configurations, the shift and cascade lemmas, W, the KC/CREL/DSTEP rules,
the Kc/Kd functions with their composition lemmas, and the fast-growing-hierarchy domination lemmas. We adapted it
to the Baker's Dozen.

This folder contains none of Jeff's files or proofs. `assemble.py` takes what the proof reuses from a checkout of
his repository at build time and puts it in place. The only lines here that also appear in his files are imports,
rows of the transition table, routine tactic lines, a few section headings, and his M12 and M14 bound statements,
quoted for the comparison.

- `BB132.v` and `Individual132.v`, his 13-state instantiation of busycoq from `BB13/verify/multifile/`, are used
  whole. The build keeps his logical path `BB8`, so they need no change.
- About 770 lines of his M12 proofs are used unchanged. In the templates `BB13_BakersDozen.v.in` and
  `BB13_BakersDozen_bound.v.in`, each reused block sits between
  `(* ---- copied unchanged from <file>: <lemma names> ---- *)` and `(* ---- end of copied block ---- *)`, and its
  body is one or two lines such as `(* insert BB12_M12.v lines 53-69 *)`. `assemble.py` replaces each such line
  with those lines of his file. The proofs then run unchanged against the Baker's Dozen's table, which agrees with
  M12's on every slot they read.
- `assemble.py` checks the SHA-256 of each of his four files before using it, and of each assembled file after,
  against the values from the recorded build. So the files that compile are exactly the recorded ones.
- Not used: M12's `D_REL_aux`, `D_REL` and `D_reload` (they read L0), `c_end_halted` (`c_end` does not halt in
  the Baker's Dozen), `init_53`/`init_352` (M12's start) and M12's run.

count non-blank lines.

A practical note for anyone extending this: the constants d1 … d4, pb4 and W 6 3 are f_ω-sized, and Coq's
unifier will try to evaluate them if a tactic (`set`, `rewrite`, `lia`/`mods`, a mistaken `apply`) compares them
with a different term. The first versions of `d2_res` and `B_strong_ge` ran out of memory this way. So all the
arithmetic about them is done in lemmas over variables (`res_81_27`, `round_count`, `chain4_ge`, …) and then
instantiated.

## How to rebuild

You need bash, git, make, Python 3 and Coq 8.20.1. In this folder, run

    bash build.sh

It fetches [github.com/jeff87654/busy-beaver](https://github.com/jeff87654/busy-beaver) at commit `f7975bf` and
[busycoq](https://github.com/meithecatte/busycoq) at commit `bd2e36f` into `deps/`. It builds busycoq's `Flip.vo`
and `Individual.vo`, assembles the four `.v` files into `build/` and compiles them there, then runs the probe. The
last lines should read

       17 of 17 Print Assumptions closed under the global context (main theorems and rules)
       build/probe.log is identical to the recorded probe.log

With opam, run `opam exec --switch=<your 8.20.1 switch> -- bash build.sh`. To use copies you already have, set
`BUSY_BEAVER` to a busy-beaver checkout, or `BUSYCOQ` to a busycoq `verify/` directory with `Flip.vo` and
`Individual.vo` built. Under WSL, work on the Linux filesystem, since `/mnt/c` is slow.

The recorded run, `build.log`, started from a fresh copy of this folder in WSL Ubuntu and took under 20 s,
including the fetches. `BB13_BakersDozen.v` takes 6 s of that. Any copy of Jeff's repository works if its four
files match commit `f7975bf`, and `assemble.py` says whether they do.

To regenerate the probe, run `python gen_probe.py` in this folder.

## Not proved here

- **Step count.** No step count is computed.
- **Upper bound.** No upper bound on σ is proved.
- **Seed.** The seed f_ω(4) is not optimized (f_ω1(f_ω(4) − 1) is available on paper). The strong theorem keeps the
  extra f_ω at each round that the plain form drops.
